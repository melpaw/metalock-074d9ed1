# Migration Checklist — Off-Platform Independence

This document is the audit trail for running MetaLock without the
Lovable web IDE, using only **VS Code + GitHub + Supabase +
Cloudflare**. It complements the technical docs in
[`docs/`](./docs).

## 1. Dependencies

All runtime and dev dependencies are public npm packages. See
[`package.json`](./package.json) for the pinned versions.

### Runtime
`@hookform/resolvers`, all `@radix-ui/*` primitives,
`@supabase/supabase-js`, `@tailwindcss/vite`, `@tanstack/react-query`,
`@tanstack/react-router`, `@tanstack/react-start`,
`@tanstack/router-plugin`, `class-variance-authority`, `clsx`,
`cmdk`, `date-fns`, `embla-carousel-react`, `i18next`,
`i18next-browser-languagedetector`, `input-otp`, `lucide-react`,
`react`, `react-day-picker`, `react-dom`, `react-hook-form`,
`react-i18next`, `react-resizable-panels`, `recharts`, `sonner`,
`tailwind-merge`, `tailwindcss`, `tw-animate-css`, `vaul`,
`vite-tsconfig-paths`, `zod`.

### Dev
`@eslint/js`, `@lovable.dev/vite-tanstack-config` ⚠️,
`@types/node`, `@types/react`, `@types/react-dom`,
`@vitejs/plugin-react`, `eslint`, `eslint-config-prettier`,
`eslint-plugin-prettier`, `eslint-plugin-react-hooks`,
`eslint-plugin-react-refresh`, `globals`, `nitro`, `prettier`,
`typescript`, `typescript-eslint`, `vite`.

⚠️ `@lovable.dev/vite-tanstack-config` is a **Lovable-published
preset** that bundles: `@tanstack/start` Vite plugin, React plugin,
Tailwind v4, tsconfig-paths, Nitro (Cloudflare Workers preset by
default), dev-only component tagger, VITE env injection, `@` path
alias, React/TanStack dedupe. It is a normal public npm package,
installs cleanly outside Lovable, and does not phone home. It is
kept because replacing it is a large change that would require
re-wiring all of the above by hand. See section 4 for the
migration path if you want to remove it later.

## 2. Environment variables

Documented in [`.env.example`](./.env.example) and
[`docs/env.md`](./docs/env.md).

Required to run:
- `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_PROJECT_ID`
- `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_PROJECT_ID`

Required for privileged server code (only if used):
- `SUPABASE_SERVICE_ROLE_KEY`

## 3. External services

| Service | Purpose | Required |
| ------- | ------- | -------- |
| Supabase | Postgres, Auth (GoTrue), Storage, optional Edge Functions | ✅ |
| Cloudflare Workers (or equivalent) | SSR + server functions runtime | ✅ |
| CoinGecko public API | Live crypto prices via `src/lib/prices.functions.ts` | ✅ (no key) |
| Google Fonts (`fonts.googleapis.com`) | Inter font with `display=swap` | ✅ (no key) |
| GitHub | Source control | recommended |
| Google OAuth | Optional sign-in provider | optional |
| SMTP | Password reset / auth emails — configured in Supabase Dashboard | optional (Supabase built-in works) |

## 4. Credentials to configure in a fresh environment

- Supabase anon key + URL + project ref (Dashboard → Project Settings → API).
- Supabase service role key (only if you use `supabaseAdmin`).
- Cloudflare account + API token with Workers Edit permission for `wrangler deploy`.
- (Optional) Google OAuth client ID/secret — set in Supabase Dashboard, not `.env`.
- (Optional) Custom SMTP credentials — set in Supabase Dashboard.

## 5. Run locally

```bash
git clone <repo>
cd metalock
cp .env.example .env      # fill in real values
npm install
supabase link --project-ref <ref>
supabase db push
psql "$SUPABASE_DB_URL" -f supabase/seed.sql   # dev only
npm run dev                # http://localhost:8080
```

Full detail in [`docs/install.md`](./docs/install.md).

## 6. Deploy to production

```bash
npm run build                                # produces .output/
wrangler secret put SUPABASE_URL             # + PUBLISHABLE_KEY, PROJECT_ID
wrangler secret put SUPABASE_SERVICE_ROLE_KEY # if used
wrangler deploy
```

Full detail (including Pages Functions and non-Cloudflare hosts)
in [`docs/deploy.md`](./docs/deploy.md).

## 7. Restore the database from scratch

The entire schema is in `supabase/migrations/`. To recreate:

```bash
supabase db reset          # local — applies all migrations + seed.sql
# or, against a linked remote:
supabase db push
```

Data restore is documented in
[`docs/backup-and-recovery.md`](./docs/backup-and-recovery.md).

## 8. Files still auto-generated by Lovable

The following are safe to keep as-is, but **regenerate on the next
Lovable sync** — do not hand-edit:

- `src/integrations/supabase/client.ts`
- `src/integrations/supabase/client.server.ts`
- `src/integrations/supabase/auth-middleware.ts`
- `src/integrations/supabase/auth-attacher.ts`
- `src/integrations/supabase/types.ts`
- `src/routeTree.gen.ts` — regenerated by TanStack Router plugin.
- `supabase/config.toml`
- `.env` (project-specific values)

Off-platform, `types.ts` regenerates with
`supabase gen types typescript --linked > src/integrations/supabase/types.ts`.
The other Supabase integration files are stable Supabase JS
boilerplate; keep them or replace with your own equivalent — the
imports (`@/integrations/supabase/*`) are used throughout the app,
so keep the public shape identical if you rewrite them.

## 9. Remaining Lovable coupling points

| Coupling | Where | Impact if removed | Migration path |
| -------- | ----- | ----------------- | -------------- |
| `@lovable.dev/vite-tanstack-config` preset | `vite.config.ts` | Vite dev/build stops until re-wired manually | Replace with explicit `plugins: [tanstackStart(), viteReact(), tailwindcss(), tsconfigPaths(), nitro({ preset: 'cloudflare-module' })]` in `vite.config.ts`. Follow the preset's README for exact options. |
| `reportLovableError` beacon | `src/lib/lovable-error-reporting.ts` + used in `src/routes/__root.tsx` and `src/server.ts` | Nothing — the beacon reads `window.__lovableEvents?.captureException`, which is undefined off-platform, so the call is a silent no-op | Optional: replace the body with a Sentry/PostHog/Datadog client. |
| `.lovable/` folder | root | Nothing — read-only metadata used by the Lovable IDE | Delete when the repo leaves Lovable. |
| `AGENTS.md`, `bunfig.toml` | root | Nothing at runtime — hints for the Lovable agent + `bun` preferences | Delete or keep as personal preference. |
| OG image on Google Cloud Storage | `src/routes/__root.tsx` | Social preview breaks | Host your own image (e.g. in `public/`) and update the URL. |
| Hard-coded domain `metalock.lovable.app` | `src/routes/index.tsx`, `src/routes/sitemap[.]xml.ts`, `public/robots.txt`, docs | Canonical + sitemap point at the old URL | Replace with your production domain, ideally via a single `VITE_SITE_URL` env var. |

## 10. What does NOT depend on Lovable

- The TanStack Start app itself.
- All application code under `src/` (routes, components, hooks,
  i18n, styles).
- The full Supabase schema (`supabase/migrations/` + `seed.sql`).
- All documentation under `docs/`.
- The build output (`.output/`) — runs on any Workers-compatible host.

Any developer with the checklist above, a Supabase project and a
Cloudflare account can clone, configure, build and deploy this
repository without touching the Lovable platform.
